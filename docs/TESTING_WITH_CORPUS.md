# Testing with the "Project Atlas" corpus

> The corpus itself lives in `data/test_corpus/`, which is **gitignored** —
> it is generated, not authored. `scripts/make_test_corpus.py` is the source
> of truth and regenerates it byte-identically.

Generated by `scripts/make_test_corpus.py`. Regenerate any time:

```bash
uv run python scripts/make_test_corpus.py
```

## Why these documents and not a random PDF

A random PDF proves the upload endpoint works. It cannot tell you whether the
table agent parsed the table, whether the KG agent found a two-hop path, or
whether fact-check caught a wrong number — because with arbitrary content you
have nothing to check the answer against.

Every document here is built so specific machinery has something to bite on,
and so **the correct answer is known in advance**. `GROUND_TRUTH.json` holds
the planted facts in one place; the transcript in
`scripts/meeting_scenario.json` deliberately contradicts some of them.

| File | Contains | Exercises |
|---|---|---|
| `01_vendor_evaluation.docx` | 5 headings, a **ruled 4×5 table** of vendor cost/latency/SLA/regions | Docling layout analysis, the table agent, element-type boosting (table rows should win for "what did it cost?" questions), section-aware chunking |
| `02_security_audit.docx` | Findings table; entities **shared with doc 1** (Acme Systems, Beacon Cloud, Priya Raman) | KG relationship extraction and 2-hop traversal — the connection only exists across the two documents |
| `03_q3_financials.pdf` | Precise figures: 15% growth, $4.2M, 22% margin, 2.1% churn, $200k budget line | Fact-check ground truth, groundedness scoring, cross-document retrieval |
| `04_master_services_agreement.pdf` | SLA/MSA acronyms, renewal date `2026-06-30`, 60-day notice, EU residency clause | Acronym resolution in the groundedness checker, date/entity extraction, decision recall |

## Running the scenario

```bash
# 1. start the stack
./run.sh          # option 1, or: uv run uvicorn apps.api.main:app --reload

# 2. generate the corpus (once)
uv run python scripts/make_test_corpus.py

# 3. drive it end to end and SCORE the result
uv run python scripts/run_test_scenario.py

# with auth on:
uv run python scripts/run_test_scenario.py --email you@example.com --password ...

# make the insight agent reachable (needs EXA_API_KEY):
uv run python scripts/run_test_scenario.py --research
```

The runner exits non-zero if a required expectation is missed, so it works as
a smoke test in a pipeline.

## What the scenario checks

The transcript has 13 utterances, each declaring which agents it *should*
trigger. Two things make it a test rather than a demo:

1. **Planted contradictions.** Two utterances state figures the corpus
   disproves ("seven findings including two critical", "revenue grew 23% to
   6.8 million"). A silent fact-check on those is a false negative.
2. **A negative case.** One utterance says *"just to recap, last month we
   decided…"* — it contains decision language but refers to an old decision.
   The scribe must **not** fire. This pins the retrospective-exclusion fix; a
   nudge there means it regressed.

There is also a correct-figures utterance ("Acme at a hundred and eighty five
thousand") where a fact-check nudge would be a **false positive** — which is
what the precision floors exist to catch.

## Agent coverage

Covered by the transcript: `agenda`, `context`, `scribe`, `fact_check`,
`kg_query`, `activation`, `flow`, `insight` (with `--research`).

**`memory` is not covered on a first run, and that is correct** — it recalls
decisions from *prior* meetings, so there is nothing to recall until the
graph has history. Run the scenario twice: the second run can surface the
first run's "go with Acme Systems" decision. That is a property of the
retention loop, not a gap in the scenario.
